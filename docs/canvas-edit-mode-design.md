## 一、产品文档

### 1.1 背景与思路

现有「编辑图片」是独立弹窗(ImageEditor:裁剪/滤镜/旋转),能力与画布割裂——而
画布本身就有顶级工具集:画笔手绘、形状、文字、素材库(2 万+ 贴图/家具/植物)、
图片拖入。**编辑一张图,本质上就是"在这张图上创作"**——所以编辑态直接复用画布:
进入后全套画布工具可用,素材往图上贴、画笔往图上画、文字往图上加,完成后把
目标图与其上的叠加元素**拍平(合并)成一张图**,原位替换原图。

Figma/Canva 哲学:画布即编辑器。这也接替了 #1(已移除)的精修定位——AI 改图走
prompt 指令(选图+描述改哪),手动精修走画布编辑态。

### 1.2 用户故事

1. 选中一张图片 → 弹出工具栏点「**编辑图片**」(入口不变,行为升级);
2. 画布顶部出现黄色横幅「**正在编辑:素材名**——可用素材库/画笔/文字在图上叠加,
   完成后合并」,画布工具全部可用;
3. 用户自由创作:从素材库拖一张沙发贴到图上、画笔圈个重点、加一行标注文字……
   (任何新元素只要落在图上都算叠加,超出图片边界的部分合并时会被裁掉);
4. 点横幅「**完成合并**」→ 目标图+其上叠加元素拍平成一张新图,**原位原尺寸替换
   原图**,叠加元素随之消失;
5. 反悔?横幅变为「已合并 — **撤销合并**」(一次性),点击恢复原图与全部叠加元素;
6. 点「取消编辑」= 不合并直接退出,叠加元素保留在画布上(用户可自行删除)。

### 1.3 功能范围

**做**:上述体验;叠加元素=编辑会话期间新加且与原图相交的任意元素(图/画笔/
形状/文字/素材);替换后一次性撤销;Esc=取消编辑(不合并)。
**不做(一期)**:其它元素硬锁定/淡化(拍平白名单保证误改不进合并,视觉锁定列
为二期增强);多层图层管理/顺序面板;ImageEditor 下线(先并存观察);非破坏性
分层保留(合并即拍平,撤销只有一次);蒙版笔特殊语义(照常作为画笔叠加)。

### 1.4 验收标准

- 选中图→「编辑图片」→ 贴素材+画笔+文字 →「完成合并」:结果为**一张图**,
  原位原尺寸,叠加元素清除,超出原图边界部分被裁掉;
- 「撤销合并」完整恢复(原图+全部叠加元素+原位置);
- 「取消编辑」叠加元素保留、原图不变;
- 素材库/画笔/文字等画布工具在编辑态全部可用(零限制);
- E2E 主流程(插入图→编辑→叠加→合并→断言单图)通过;内网 LAN 过目。

## 二、技术方案

### 2.1 架构:一个编辑会话控制器 + 现成渲染地基

```
选中图片 →「编辑图片」(popup-toolbar,行为改指编辑态)
  ↓
CanvasEditModeController(新,模块级单例)
  · 进入:记录目标图 elementId + 会话起始时间(判定"新增元素")
  · 顶栏横幅 InpaintBanner→ EditModeBanner(新建,提示/完成/取消/撤销)
  · 编辑中:画布全能力,零限制(白名单在拍平时兜底)
  ↓ 完成合并
boardToImage(board, { elements: [目标图, ...叠加元素] })   ← 现成(导出命令同款)
  · 叠加白名单=会话内新增 ∧ 与目标图矩形相交 ∧ 未被用户删除
  · 裁剪到原图矩形:boardToImage 按 elements 包围盒输出 → 若不支持指定矩形,
    输出后按原图宽高比 canvas 裁剪(动工时验证 API 形态,两路备选)
  ↓
上传 ai-outputs 桶拿直链(复用 ensureGeneratedMediaArchive,#32 插入视角同款)
  ↓
替换:删目标图+叠加元素 → insertImageFromUrl(新直链, 原位置, 原显示尺寸)
  · 撤销快照:{被删元素数据[], 新图元素} → 「撤销合并」一键恢复
```

### 2.2 关键设计

- **会话判定"新增元素"**:进入时快照现有 elementId 集合,编辑态中出现在集合外
  的即会话新增(含 undo/redo 边界:撤销掉的新增元素自然不在白名单)。
- **拍平白名单兜底正确性**:不锁工具、不锁其它元素——即使用户编辑态中动了别处
  元素,只要不与目标图相交就不会进合并;相交的**旧元素**(编辑前就有)也排除
  (只拍会话新增),避免把原有内容误合入。
- **替换实现**:removeElements([目标图, ...叠加]) + insertImageFromUrl(
  points=原图 points, size=原图显示宽高)——原图若为虚拟 URL,拍平用的
  boardToImage 已能渲染画布现有元素(渲染层现成,不受 URL 形态影响)。
- **撤销合并**:不走 Plait undo 栈(合并是多次操作,栈可能被后续操作冲掉),
  用会话快照恢复:被删元素原数据重插 + 新图元素删除;横幅消失。仅一次机会
  (再次进入编辑/继续操作后快照作废,横幅隐藏)。
- **Esc 语义**:编辑态中 Esc=取消编辑(不合并,叠加保留);与现有 Esc 冲突
  (清选区/关弹窗)按"编辑态优先"拦截一次。
- **ImageEditor 存废**:「编辑图片」改指编辑态后,ImageEditor 弹窗仍可从双击
  图片等入口进入(一期不动,观察使用)。

### 2.4 测试计划(TDD)

- 单测(vitest):会话新增判定(快照集合差集/撤销边界)、拍平白名单(相交∧新增∧
  未删)、替换几何(原位置原尺寸)、撤销快照恢复完整性。
- E2E(e2e-test-writer,1 条):插入 fixture 图 →「编辑图片」→ 从素材库拖一张
  贴图叠加(或画笔涂一笔)→「完成合并」→ 断言画布上该区域只剩一张图(元素数/
  图片元素 url 变化)→「撤销合并」→ 断言原图与叠加恢复。
- 门禁:check/vitest 全量/后端;内网 LAN 过目(合并/撤销/取消三路径)。

### 2.5 工作量与风险

~4 个工作日:会话控制器+横幅 1d → 拍平+裁剪+桶上传+替换 1.5d → 撤销快照 0.5d
→ 单测+E2E+过目 1d。

风险与对策:
1. **boardToImage 对指定矩形/元素集的支持形态**(包围盒 or 含 padding)——动工
   第一件事用小图实测,按实测包裁剪;导出命令同款调用已证明可用性;
2. 大图高分辨率拍平内存——boardToImage 输出尺寸受画布渲染约束,必要时按原图
   自然尺寸分块/上限(先实测,超预期再加 fitMaskSizeToMaxPixels 同款约束);
3. 虚拟 URL 图片在拍平渲染中的表现——渲染走画布 DOM/离屏渲染与显示同源,
   理论无新风险,实测覆盖 AI 生成图(虚拟 URL)与桶直链图两类。

## 三、明确不做(一期)

其它元素硬锁定/视觉淡化(二期增强);图层顺序面板;非破坏分层(合并即拍平);
ImageEditor 下线;多人/多画布并发编辑会话;合并结果二次编辑特殊化(结果就是普通
图片元素,天然可再次进入编辑态迭代)。
