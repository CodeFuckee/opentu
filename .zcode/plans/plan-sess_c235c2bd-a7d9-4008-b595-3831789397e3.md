# 生图月度额度管控方案(每人每月 200 张 · 服务端硬管控)

## 架构

```
浏览器(Yue画布, 不再存API Key)
   │  Authorization: Bearer <Supabase JWT>
   │  原 request.path/body 原样透传
   ▼
新边缘函数 ai-proxy(Supabase, 内网 10.37.80.25:8021)
   1. 验证 JWT → 得到可信 auth.uid()
   2. 原子扣减 generation_usage(RPC, 自然月≤200, 失败自动退回)
   3. 用 user_profiles.apikey 注入鉴权头, 转发到自建 new-api(NEWAPI_URL)
   4. 结果原样返回前端; 轮询(GET /videos/{id}、/mj/task/…)同样透传,
      从轮询响应识别"最终失败"并自动退回额度
```

关键点:
- 前端约 18 个调用点全部经 `providerTransport.send()`(packages/drawnix/src/services/provider-routing/provider-transport.ts:187),在这层做托管改写,**多协议适配器逻辑零改动**。
- API Key 只存在于服务端数据库,浏览器没有可滥用凭据,无法绕过。
- 月度边界用 SQL `date_trunc('month', now()+tz)` 惰性计算,**无需定时任务**。

## 实施步骤

### 0. OpenSpec 提案(项目规范强制要求)
按 `openspec/AGENTS.md` 创建变更提案并跑通校验:
- change-id: `add-image-generation-quota`
- 写 proposal.md / tasks.md / specs delta("图像配额管控"capability)
- `openspec validate add-image-generation-quota --strict` 通过后再实现。

### 1. 数据库迁移 `supabase/migrations/generation_usage.sql`(沿用现有纯 SQL 文件风格)
- 表 `generation_usage(user_id, period(该自然月首日), used_count, updated_at, unique(user_id, period))`,启用 RLS,仅允许本人 select。
- SECURITY DEFINER 函数:
  - `consume_image_quota(p_user_id, p_count)`:INSERT..ON CONFLICT DO UPDATE 单语句原子累加,`WHERE 累加后≤限额`;超限返回未命中(代理据此拒绝)。限额读 `department_configs`(key=`image_monthly_quota_default`,缺省 200),后续可做部门差异化。
  - `refund_image_quota(p_user_id, p_count)`:`used_count=greatest(0, used-n)`。
  - `get_image_quota(p_user_id)`:返回 {limit, used, remaining}。
- EXECUTE 权限仅授予 `service_role`(前端一律通过代理访问,不给 anon/authenticated 直调写入口)。

### 2. 边缘函数 `supabase/functions/ai-proxy/`(沿用 index.ts + core.ts + core.test.ts 三件套模式)
index.ts(Deno 入口)/ core.ts(纯逻辑, 可注入 fetch 测试):
- 鉴权:取 `Authorization: Bearer` JWT → `GET {SUPABASE_URL}/auth/v1/user` 验证,得 uid;无效返回 401。
- 通用转发:`{SUPABASE_URL}/functions/v1/ai-proxy/<原path>?<query>` → `{NEWAPI_URL}/<path>?<query>`(URL 从 configs.NEWAPI_URL 读),注入 `Bearer user_profiles.apikey`(service_role 读取)。**不解析、不修改业务 payload**。
- 计费分类(v1 规则,记录在 design.md):
  - 同步生图:`POST images/generations|images/edits`(从 body.n 取张数,默认1)、`POST mj/submit/*`(1张)、流式 Gemini 图像调用按 1 次/请求近似计;
  - 异步图像提交(如 `/videos` 类表单):按任务创建时记 1 条 pending;
  - 上游响应 ≥400 → 立即自动退回;
  - 轮询响应中出现终态 FAILED/CANCELLED/EXPIRED → 一次性退回(pending 表防重复);
  - 仅管控"图";文本/音频/视频类直接透传不计数。
- `GET .../quota`:调 get_image_quota 返回剩余,供前端展示。
- 首次调用发现 `user_profiles.apikey` 为空 → 内部自调既有 `newapi-key` 函数补铸造后重试(幂等,复用注册期逻辑)。
- 处理 OPTIONS/CORS,复用现有函数的部署方式(拷贝到服务器 volumes/functions 目录热加载);已知环境变量 SUPABASE_URL、SUPABASE_SERVICE_ROLE_KEY,新增读取 configs 表的 NEWAPI_URL 与默认限额。
- core.test.ts(node --test,注入 fake fetch):覆盖 鉴权失败/扣减拒绝/同步退回/异步终态退回/透传不改写 等用例。

### 3. 前端 — packages/drawnix(核心改动集中在此)
- 新增 `services/managed-routing/managed-runtime.ts`:轻量运行时注册器(setter 存 {supabaseUrl, getToken(), enabled}),apps/web 在启动时注入。drawnix 包本身零 supabase 依赖,依赖方向不变。
- `provider-transport.ts` 的 prepareRequest 中增加托管分支:image 类操作且托管开启时——baseUrl 改写为代理、丢弃本地 apiKey/authType,Authorization 改为 `<当前会话JWT>`;在 ProviderTransportRequest 类型上加可选 `billing.kind='image'` 字段标记可计费提交点(fallback-executor、media-api/image-api.ts、async-image-api-service.ts、mj 提交处由执行器已知 TaskType 标注,代理信任此标记并结合路径白名单双重校验)。
- 凭据判定改造:`resolveInvocationRoute` / `hasInvocationRouteCredentials('image')`(settings-manager.ts)在登录+托管模式下对 image 操作恒返回"就绪"且忽略本地手填 profile → 设置弹窗不再弹 `promptForApiKey()`(gemini-api/auth.ts 的 DOM 弹窗与 ?apiKey= URL 注入对该路由自然失效保留不动)。
- 额度 UI:`useImageQuota()` 小钩子(走代理 /quota):AI 生图弹窗(ai-image-generation.tsx)、批量弹窗(batch-image-generation.tsx)顶部显示"本月剩余 X 张";点击生成时预检查(仅优化体验,服务端才是权威);收到 403/429 配额错误时统一转成友好提示"本月 200 张额度已用完"。画布输入栏、漫画创作等入口因共用执行栈自动纳入。

### 4. 前端 — apps/web(桥接)
- `auth-context.tsx` 暴露 `getAccessToken()`(内部基于已有 session 自动刷新);bootstrap/app 层根据登录态调用 `configureManagedRouting({supabaseUrl, getToken, enabled})`;登出时置 disabled 并提示重新登录。

## 已知限制(写入文档,非阻塞)
- 自托管边缘容器有单请求时长上限,需在验收清单确认;慢队列模型(MJ 等)极端情况下可能触及该上限,后续可演进为"提交即返 jobId"模式。
- new-api 平台侧账户配额(注册时 200)继续保留作为纵深防御,不再依赖它折算"张数"。
- 另:仓库根目录 secret.md 含生产库密码明文已入库,建议尽快处理(与本需求无关,顺带提醒)。
