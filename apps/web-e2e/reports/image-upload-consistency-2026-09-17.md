## 核心结论：粘贴行为「不一致」的真实结构（用户实测反馈已证实）

用户在预览站实测「直接复制粘贴 >25MB 文件可以」「左侧边栏上传 >25MB 可以」，与此前
E2E-IMG-02（粘贴被拒）矛盾。排查后确认两者都是真的，取决于**粘贴时焦点在哪里**：

| 粘贴目标状态 | 行为 | 用例 |
| --- | --- | --- |
| 聚焦 AI 输入条后粘贴 | AIInputBar 接管 → 25MB 校验 → 拒绝提示 | E2E-IMG-02 ✅ 拒绝 |
| 不聚焦输入条（画布激活）直接粘贴 | plait 画布 paste 监听 → 无任何校验 → 图片直接插入画布 | E2E-IMG-12 ✅ 接受 |
| 左侧边栏「图片」工具选择 >25MB 文件 | browser-fs-access fileOpen → insertImage → 无校验插入画布 | E2E-IMG-13 ✅ 接受 |
| 左侧边栏「素材库」上传 >25MB | 素材库上限 100MB → 接受入库 | E2E-IMG-10 ✅ 接受 |

即：**25MB 校验只存在于「图片进生成任务」的 UI 路径上；画布级粘贴/插入完全没有校验**。
用户日常「直接粘贴」走的正是画布路径，所以观感是「没有限制」。

## 调试过程中发现的应用事实（未修代码，已如实记录）

1. **画布粘贴静默忽略条件**：board.selection 为空（空白新画布首次粘贴）时，paste 事件被
   守卫静默跳过——不插入、无提示。画布上存在选中元素后粘贴正常。测试以先绘制矩形建立
   选中态的方式确定化。
2. 大图插入画布全链路（解码 18187×12260 / 内容哈希 / Cache Storage 50MB 写入）均正常
   （各步骤独立验证通过，50MB 插入 3 秒内完成）。
3. **已确认 bug（用户定性，未修代码）**：空白画布（board.selection 为空）直接粘贴图片被**静默忽略**——
   不插入、无提示、无报错，50.67MB 真实文件连续 3 次尝试均忽略（E2E-IMG-14 以 fixme 固化，
   断言期望行为「应插入画布」；应用修复后移除 fixme 即转正式回归）。
4. 已知缺口与此前版本报告一致：批量生图无校验（IMG-09）、素材库→AI 输入条路径无校验（IMG-11）。
   另：先绘制矩形再粘贴 >25MB 同样无提示直接插入（IMG-12 固化，用户已确认该现状）。
