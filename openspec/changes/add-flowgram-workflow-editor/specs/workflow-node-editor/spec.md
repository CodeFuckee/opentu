# workflow-node-editor 能力增量

## ADDED Requirements

### Requirement: 全屏编排编辑器视图

应用提供 `/workflow` 全屏节点编排编辑器（基于 Flowgram free layout）：左侧节点面板、中央节点画布、右侧参数面板、minimap 与顶栏；主画布经工具箱「打开编排器」进入，编辑器顶栏可返回画布；刷新 `/workflow` 直达不 404。

#### Scenario: 从工具箱进入编辑器并返回

- **WHEN** 用户在主画布打开工具箱并点击「工作流编排器」，随后点击顶栏「返回画布」
- **THEN** 浏览器进入 `/workflow` 全屏编辑器且主画布数据不受影响；点击返回后回到原画布，`?board=` 上下文保留

#### Scenario: 刷新直达

- **WHEN** 用户在 `/workflow` 页面直接刷新
- **THEN** 编辑器重新加载（SPA fallback / SW app-shell 兜底），不出现 404

### Requirement: 节点编辑与图管理

编辑器支持添加 8 种编排节点（提示词/参考图/模型与参数/文生图/基于图生成/插入画布/存素材库/预览）、端口到端口连线、删除节点与连线、编辑节点参数；图以具名工作流保存/打开/删除，持久化复用既有编排图存储（含 schemaVersion 迁移），存量图可直接打开。

#### Scenario: 搭建并保存工作流

- **WHEN** 用户在编辑器添加「提示词」「文生图」「存素材库」节点，按 提示词→文生图→存素材库 连线并填写提示词后保存
- **THEN** 图以当前 schemaVersion 持久化，图列表出现该具名工作流，刷新后重新打开节点/连线/参数完整

#### Scenario: 打开存量图

- **WHEN** 用户在编辑器图列表中选择一张旧版本 schema 的已存图
- **THEN** 读取时按既有迁移函数升级到当前版本并正常显示，保存后以当前版本落盘

### Requirement: 编辑器内运行与状态反馈

编辑器内可运行当前图：复用既有图编译器与执行引擎（与画布编排同底座），节点显示 pending/running/completed/failed 状态徽标与错误摘要；需要画布上下文的落地节点（插入画布/存素材库）在编辑器内运行时该步骤明确标示失败并提示回画布运行，不阻断其余节点执行。

#### Scenario: 编辑器内运行生图链路

- **WHEN** 用户运行「提示词→文生图→预览」工作流
- **THEN** 文生图节点经 running 转 completed，预览节点可查看生成图；全程各节点状态徽标与执行一致

#### Scenario: 无画布上下文的落地步骤

- **WHEN** 用户在编辑器内运行含「插入画布」节点的工作流
- **THEN** 插入画布步骤标 failed 并提示回画布后运行，其余节点正常执行不受阻断

### Requirement: 主画布首屏与数据零影响

编辑器代码为独立懒加载 chunk，主画布首屏不加载编辑器依赖；编排图数据与画布编排共用同一存储与云同步通道，两边对同一张图的读写遵循同一 schema，互不产生第二套图模型。

#### Scenario: 主画布首屏不受影响

- **WHEN** 用户仅访问主画布，从不进入 `/workflow`
- **THEN** 主画布首屏网络请求中不包含编辑器 chunk，画布编排功能行为不变
